      인증서 현황 · 개인키 보호

      배포 승인
      승인 정책이 켜진 인증서는 갱신본을 서버에 배포하기 전에 담당자 승인이 필요합니다. 승인은 그 인증서에만 유효하며 기한이 지나면 만료됩니다. 승인 후 배포는 다음 갱신 점검 때 자동으로, 또는 서버에서 certdeploy deploy 로 즉시 반영됩니다.

      메일 알림 펼치기
      비워 두면 저장된 값을 유지합니다. 화면에는 표시되지 않습니다.
      메신저 웹훅 (Teams·Slack·Mattermost·Google Chat·Discord) 펼치기
      주소 안에 토큰이 들어 있어 비밀로 취급합니다. 비워 두면 저장된 주소를 유지합니다(화면에는 표시되지 않음).
      티켓 시스템 연동 (ServiceNow·Jira·일반) 펼치기
      장애 알림이 처음 생기면 티켓을 만들고, 해소되면 닫습니다. 같은 대상의 열린 티켓이 있으면 새로 만들지 않습니다. 「접속 확인」은 티켓을 만들지 않고 주소·인증만 확인합니다.
      ServiceNow·Jira 는 서버 기본 주소, 일반은 티켓을 만드는 POST 주소
      비밀번호·토큰을 비워 두면 저장된 값을 유지합니다(화면에는 표시되지 않음).
      공통 알림 설정
      같은 대상의 같은 장애 알림을 이 시간 안에는 메일·웹훅으로 다시 보내지 않습니다. 0 이면 실행할 때마다 보냅니다. 권장 24.
      어떤 때 알림이 가나요?
      상황심각도알림 경로
      배포 실패 / 롤백됨치명이 화면에서 설정한 채널 + 감시 스택(Alertmanager)
      배포 승인 대기, 수동 교체 대기경고이 화면의 채널 (오래되면 감시 스택이 추가 경고)
      백업 실패 / 일부 누락치명 / 경고이 화면의 채널 + 감시 스택
      인증서 만료 임박(30·14·7·3일 전)정보~치명감시 스택(Alertmanager) — 설치할 때 정한 수신 메일
      배포 성공 요약정보채널별 「성공 요약도 보내기」를 켠 경우만
      관리 서버 백업
      매일 자동으로 설정·상태·관리자 DB·감시 비밀·nginx 를 암호화해 백업하고, 복호화로 검증한 뒤 외부 대상에도 복사합니다. 설정과 지금 실행은 서버에서 합니다(certdeploy backup-run, 설치 매뉴얼 10-4). 백업 비밀번호는 서버 밖에도 따로 보관하세요 — 잃으면 복구할 수 없습니다.

      서버 등록

      전용 읽기 전용 계정
      선택한 OS 계열의 표준 인증서 경로를 자동으로 조회합니다. 자동 감지는 접속 후 /etc/os-release 로 판단합니다.
      실행 중 서비스 인증서를 직접 조회
      표준 경로(nginx·apache·letsencrypt 등)는 자동 조회됩니다. 그 밖의 경로만 추가하세요. 탐지 버튼은 서버를 저장하지 않고 호스트·포트·계정으로 접속해 확인합니다.
      SSH 인증은 ssh-agent 개인키만 사용합니다. 패스워드는 저장·사용하지 않습니다.
