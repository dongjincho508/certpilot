# VM 구성 전 준비 체크리스트

VM(관리 서버)을 만들기 **전에** 사람이 결정·수집·요청해야 하는 모든 것. 코드와 자동 테스트는 준비되어 있으므로([검증 보고서](verification-report.md)), 이 문서의 항목이 끝나면 [설치 매뉴얼](vm-install-and-test.md)을 그대로 따라 하면 된다.

> **기한**: RapidSSL 와일드카드 **2026-11-12 08:59(KST) 만료**. VM 시험이 늦어져도 이 날짜는 움직이지 않는다 → **11/5(D-7)에 "새 방식(발급·배포 자동화)을 쓸지 / 기존 수동 교체로 확정할지" 결정**한다. 기존 방식 절차는 [교체 체크리스트](cert-rotation-checklist.md).

**D1 참고 — 갱신 주기**: CA/브라우저 포럼 결정(SC-081v3)으로 최대 유효기간이 **현재 200일 → 2027-03-15 부터 100일 → 2029-03-15 부터 47일**로 줄어든다([DigiCert](https://www.digicert.com/blog/tls-certificate-lifetimes-will-officially-reduce-to-47-days), [SSL Insights](https://shop.sslinsights.com/blog/ca-browser-forum-47-day-certificate-roadmap/)). 수동 갱신은 2027년 이후 연 4회, 2029년 이후 연 8회가 되므로 **자동 발급(ⓑ, 또는 RapidSSL ACME 플랜)으로 가는 것이 장기 방향**이다. RapidSSL "Automate"(ACME) 플랜 존재는 판매처 공지 기준이며 구매 전 RapidSSL 에 직접 확인한다(EAB 가 필요한 CA 는 현재 내장 ACME 미지원).

### C. DNS 정보 (도메인마다: `hnu.kr`, `hannam.ac.kr`)

### D. 웹방화벽(모니터랩 AIWAF/AIWAAP) — 제조사·담당자에게
1. 인증서 교체용 **관리 API 문서**가 있는가(인증 방식, 세션/CSRF)? **CLI(SSH)** 로 교체 가능한가?
2. 받는 형식(PEM 텍스트/파일 업로드/PFX+비밀번호)
3. **업로드 뒤 '적용' 단계**(이 장비는 별도 단계가 있음 — 확인됨): 적용이 인증서만 반영하나, 대기 중인 **다른 설정 변경까지 한꺼번에 반영**하나? 적용 때 서비스 순단은?
4. 같은 이름으로 덮어쓰기 가능한가, 이전 인증서로 되돌리는 방법
5. 이중화(HA) 구성: 한쪽에 올리면 동기화되나, 양쪽에 모두 올려야 하나
6. 가상 호스트별로 인증서가 따로 걸려 있나(여러 번 올려야 하나)
7. 시험용 장비/가상 호스트를 쓸 수 있나
→ 답이 오면 [호환성 가이드](compatibility.md) 형식으로 설정을 채우고 T-18 로 시험한다. **API/CLI 가 없으면 WAF 만 수동 교체**하고 나머지는 자동화한다.
### E. 알림 정보
SMTP 릴레이(주소·포트·인증 여부·발신 주소·허용 IP 에 관리 서버 등록), 수신자 목록, (사용 시) Teams 웹훅 URL — **URL·비밀번호는 채팅·메일로 보내지 말고 설치 당일 서버에서 직접 입력**.

## 3. 요청할 것 (복사해 쓰는 요청 문구)
### 전산실/인프라 — VM
> Rocky Linux 10.x 관리 서버 1대: 4 vCPU / 8 GB / 디스크 100 GB 이상(`/var` 40 GB↑), UEFI, VMXNET3, 고정 IP·호스트명(`mgmt.…`)·내부 DNS 등록, Rocky 10.x Minimal ISO. **CPU 호환성(EVC) 이 x86-64-v3(AVX2) 이상**(구형 호환 모드면 설치 불가). 폴더/권한을 일반 업무 VM 과 분리하고 콘솔·스냅샷·내보내기 권한은 최소 인원에게만. 스냅샷은 작업 직전에만 사용.
### 네트워크/보안 — 방화벽 (출발지는 모두 관리 서버, 별도 표기 제외)
| 방향 | 목적지 | 포트 | 용도 |
|---|---|---|---|
| 관리자 PC → 관리 서버 | 관리 서버 | TCP 22, 443 | SSH, Grafana(HTTPS) |
| → 대상 서버들 | 각 서버 | TCP 22 | 배포(SSH) |
| → 대상 서버들 | 각 서버 | TCP 443, 8443 등 서비스 포트 | TLS 감시·배포 후 확인 |
| → Infoblox Grid Master | WAPI 주소 | TCP 443 | DNS TXT 등록(연동 모드) |
| → 권한 DNS | 네임서버 | UDP/TCP 53 | 전파 확인, RFC2136 갱신(TCP) |
| 인터넷 → 권한 DNS | 네임서버 | UDP/TCP 53 | Let's Encrypt 검증 서버의 TXT 조회(권한 DNS 방화벽에서 허용 필요) |

| 서비스 중단(재로드 실패) | 사용자 영향 | canary 순서, 자동 롤백, 점검 시간대 배포 |
| 수동 갱신 누락 | 만료 | 감시 알림 60/30/14/7일, 갱신 달력, 2027-03-15 부터 100일 주기 대비 |
