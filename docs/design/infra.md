# 인프라 연동 설계 (INFRA_CONNECTOR)

## 1. SSH 연동

- **지원 버전**: OpenSSH 7.0 이상
- **기본 포트**: 22 (비표준 포트는 등록 시 필수)
- **인증**: 개인키 + ssh-agent (패스워드 미지원)
- **호스트 키**: TOFU + 변경 탐지 시 조회 차단
- **연결 판정**: 인증 성공까지 세션 수립 (TCB 개방만으로 판정 안 함)

## 2. 연결 타임아웃/재시도

- **타임아웃**: 10초
- **재시도**: 2회 + 지수 백오프
- **실패 분류**: DNS 실패, 연결 시간 초과, 인증 실패, 호스트 키 불일치, 접속 권한 거부, 원격 명령 실행 실패 (6종, 미분류 없음)

## 3. 실패 처리

- DNS 실패·연결 시간 초과: **재시도** (최대 2회, 지수 백오프)
- 인증 실패·접속 권한 거부·호스트 키 불일치: **즉시 실패** (재시도 없음)
- 원격 명령 실행 실패: **원격 명령 실행 실패**로 분류 (허용 명령 목록 밖 실행 시도 포함)

## 4. 원격 명령 허용 목록 (B-5) — 고정 읽기 전용 (구현: `remote.CommandPolicy`)

PRD §3.1.2 의 집합 그대로: `cat` `head` `tail` `grep` `ls` `find`(화이트리스트 내) `sha256sum` `openssl x509 -noout -dates|-subject|-issuer|-serial`.
셸 메타문자, 파이프, `sudo`, `chmod/chown`, `curl/wget`, `ssh/scp`, `find -exec/-delete`, 화이트리스트 밖·`..` 경로는 모두 거부한다. 현재 스캐너가 실제로 쓰는 것은 `ls -1 -p`, `ls -l`, `head -c N` 뿐이다.

## 5. 포트 기반 조회 (B-3) — 구현 결정 DD-1

이전 초안의 `ss -tlnp`·`openssl s_client` 원격 실행은 PRD 허용 명령에 없어 **채택하지 않았다**.
- 포트 목록: 서버 등록 시 지정(`tls_ports`). 원격 열거 없음.
- 핸드셰이크: **관리 서버가 직접** TLS 연결(SNI=호스트명, 검증 없이 인증서만 수신).
- 실패 매핑: DNS→`DNS`, 거부/시간 초과→`TIMEOUT`, TLS 핸드셰이크 실패→`COMMAND`(원격 환경 확인). 재시도는 DNS/시간 초과만.
- 방화벽: 관리 서버→대상 포트 개방 필요(운영 절차).

## 6. Windows/장비
- 차기 단계 (MVP 제외). 제외: bastion, 컨테이너, 전체 탐색, CRL/OCSP
