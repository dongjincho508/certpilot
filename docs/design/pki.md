# PKI 설계 (PKI_ENGINE)

## 1. 인증서 파싱

- **지원 형식**: PEM, PKCS#12, JKS
- **MVP 제외**: DER 바이너리, PKCS#11 하드웨어 토큰

## 2. 키스토어 파싱 정책 (Q-KEYSTORE)

> **결정 (B-4)**: 메타데이터(존재·만료일)만 확인, 내용 파싱 제외.
> - 인증서만 추출하고 키 엔트리는 열거하지도, 값을 읽지도 않는다.
> - PKCS#12 MAC 무결성 검증과 내용 파싱은 MVP에서 제외.
> - 패스프레이즈는 메모리에만 존재시키고 명령행·로그·설정 파일에 남기지 않는다.

## 3. 상태 머신

- **상태**: 정상 → 만료 임박 → 만료 (독립)
- **별도 상태**: 유효 전(미발급), 체인 위험 (중CA/루트), 조회 실패, 인증서 미발견, 확인 필요
- **판정 기준**: 관리 서버(수집) 시각 UTC, `now >= notAfter` → 만료, `now >= notAfter − T` → 만료 임박

## 4. 발급·갱신

- MVP 제외 (후속 단계)

- 보존/접근 통제 (B-4 보완): 개인키 미접근은 '메타데이터(존재·만료 보증)만 확인 + 내용 파싱 제외'로 보장한다.
  - 키스토어는 전용 최소권한 계정이 읽기 전용으로 접근하고, 접근 시도(성공/실패)는 감사 로그에 기록한다.
  - 패스프레이즈는 조회 시 메모리에만 존재하며 명령행·로그·설정 파일에 노출되지 않는다.
  - 키스토어는 파싱하지 않으므로 키 자재를 저장소에 보존하지 않는다 (존재 여부·만료일만 수집).

## 6. 종속성

- Q-FORMAT (PEM + PKCS#12 + JKS)
- Q-SSHAUTH (개인키 + ssh-agent)
- Q-KEYSTORE (인증서만 추출)
- Q-EXPRULE, Q-DAYCALC, Q-WARN
