## 1. 프로젝트 목적

CertPilot은 서버 및 인프라 환경의 인증서 상태와 만료 위험을 통합적으로 확인하기 위한 인증서 수명주기 관리 솔루션이다.

첫 번째 MVP에서는 Linux 서버를 대상으로 SSH를 통한 인증서 정보 조회와 만료 모니터링에 집중한다. 인증서 발급·갱신·배포 자동화는 후속 단계로 분리한다.

**핵심 목표**

- Linux 서버별 인증서 현황을 조회한다.
- 인증서 만료일과 잔여 일수를 확인한다.
- 만료 임박 및 만료 상태를 식별한다.
- 연결 실패와 조회 실패를 정상 상태와 구분한다.
- 향후 다른 운영체제, 인증기관(CA), 네트워크 장비로 확장할 수 있는 요구사항 기반을 마련한다.

**성공 지표(KPI)** — 신설 필요. 측정 항목·목표값·측정 주기 미정 `[미결 Q-KPI]`
> 0.1 검토 지적: 목적만 있고 MVP 성공을 판정할 측정 가능한 기준이 없었다.

## 3. MVP 범위

### 3.1 필수 기능 (P0)

#### 3.1.1 서버 관리

- 관리 대상 Linux 서버의 식별 정보를 등록·조회한다.
- 서버별 인증서 조회 대상과 조회 상태를 구분한다.
- SSH 연결 가능 여부를 확인한다.

**서버 등록 입력 항목** (0.1에서 미정의 → 신설)

| 항목 | 필수 여부 | 비고 |
|---|---|---|
| 서버명(식별자) | 필수 | 중복 허용 여부 `[미결 Q-IDENT]` |
| 호스트명 또는 IP | 필수 | |
| SSH 포트 | 필수 | 기본값 미정 `[미결 Q-SSHPORT]` |
| 접속 계정 | 필수 | 전용 계정 여부 `[미결 Q-ACCT]` |
| SSH 인증 방식 | 필수 | `[미결 Q-SSHAUTH]` |
| 인증서 조회 경로 | 조건부 | 서버별 지정 vs 표준 경로 `[미결 Q-PATH]` |
| 그룹/태그/메모 | 선택 | |

- **SSH 연결 가능 여부의 판정 기준**: TCP 포트 개방만으로 판정하지 않는다. **인증까지 성공한 세션 수립**을 기준으로 한다. `[제안 — Q-CONNCHK]`
- **등록 후 검증 절차**: 등록 시 SSH 연결 검증 단계를 사용자 흐름에 포함한다(§4).

#### 3.1.2 SSH 접속 요구사항 (0.1에서 전무 → 신설)

- 지원 인증 방식과 그 범위를 정의한다. `[미결 Q-SSHAUTH]`
- **호스트 키 검증 정책**을 정의한다. 최초 접속 신뢰 기준과 호스트 키 변경 탐지 시 동작(차단/경고)을 명시한다. `[미결 Q-HOSTKEY]`
- **최소 권한 원칙**: 조회용 계정은 인증서 파일 읽기에 필요한 최소 권한만 가지며, 쓰기·실행·권한 상승(sudo)·임의 셸 명령을 제한한다. 구현 수단은 설계 단계로 남긴다. `[제안 — Q-ACCT]`
- **연결 타임아웃과 재시도** 횟수·간격을 설정 가능한 요구사항으로 정의한다(기본값 미정). `[미결 Q-TIMEOUT]`
- **bastion(점프 호스트) 경유 접속**: 지원 여부를 결정하고, 미지원이면 §3.3에 제외로 명시한다. `[미결 Q-BASTION]`
- **지원 OpenSSH 버전·알고리즘 범위**: 지원 범위를 벗어난 서버는 사전에 '확인 필요'로 분류하는 방식을 정의한다. `[미결 Q-SSHVER]`

#### 3.1.3 조회 실패 원인 분류 (0.1에서 단일 '조회 실패'로 통일 → 세분화)

조회 실패 원인을 다음 6종으로 구분해 표시한다. `[제안 — Q-FAILCLASS]`

| 원인 | 운영자 조치 방향 |
|---|---|
| 네임 확인(DNS) 실패 | 네트워크·DNS 확인 |
| 연결 시간 초과 | 방화벽·라우팅 확인 |
| 인증 실패 | 계정·키 발급 |
| 호스트 키 불일치 | 접근 정책 확인(보안 이벤트 가능) |
| 접속 권한 거부 | 파일 권한 부여 |
| 원격 명령 실행 실패 | 원격 환경 확인 |

> 근거: 0.1의 단일 '조회 실패'로는 네트워크/계정/권한 문제를 구분할 수 없어 운영 조치가 불가능하다(Linux & SSH 검토).

#### 3.1.4 인증서 조회

- 사전에 지정한 인증서 위치에서 조회 가능한 인증서 정보를 수집한다.
- 인증서의 식별 정보, 발급자, 주체, 유효 시작일, 만료일을 표시한다.
- 조회 실패, 인증서 미발견, 형식 오류를 구분한다.
- 실제 인증서나 개인키를 변경하지 않는 조회 중심 기능으로 제한한다.

**조회 대상 방식** (0.1에서 "사전에 지정한 위치"로 모호 → 명확화 필요) `[미결 Q-MODE]`
- (a) 디스크 파일 기반 (b) 실행 중 서비스(포트) 기반 (c) 둘 다 중 선택해야 한다.

**지원 인증서 형식·컨테이너** (0.1에서 미정의 → 신설) `[미결 Q-FORMAT]`

| 구분 | 항목 |
|---|---|
| MVP 포함 후보 `[제안]` | PEM(Base64, .crt/.pem/.cer) 단일 및 번들 |
| MVP 제외 후보 `[제안]` | DER 바이너리, PKCS#12(.p12/.pfx), JKS, PKCS#11 하드웨어 토큰 |

**조회 경로 지정** (0.1에서 모호 → 명확화 필요)
- 조회 대상은 **등록된 경로로 한정**하고, 등록되지 않은 위치는 조회하지 않는다. `[제안 — Q-PATH]`
- **경로 화이트리스트**: 허용 디렉터리·파일 패턴으로 제한하고, 상위 디렉터리 이탈·인증서 외 파일 접근을 차단한다. `[제안 — Q-PATH]` (보안 검토: 임의 파일 읽기 위험)
- **파일시스템 전체 탐색(find / 등)을 기본 동작으로 하지 않는다.** `[제안 — Q-SEARCH]`
- **심볼릭 링크 처리**: 링크를 따라갈지, 깨진 링크를 어떤 상태로 분류할지 정의한다. `[미결 Q-SYMLINK]`
- **웹 서버 설정 파일(nginx/apache)에서 인증서 경로를 자동 추출**하는 기능의 MVP 포함 여부. `[미결 Q-WEBCFG]`
- **컨테이너 내부 파일시스템·K8s 시크릿에만 존재하는 인증서**: 지원 여부를 결정하고, 미지원이면 §3.3에 제외로 명시한다. `[미결 Q-CONTAINER]`

**다중 인증서·체인 처리** (0.1에서 미정의 → 신설)
- 한 위치에 인증서가 여러 개면 각각 개별 식별·개별 상태 표시한다. `[제안]`
- 번들(체인) 파일은 리프/중간CA/루트를 구분해 식별하고 체인 위치를 표기한다. `[제안]`
- **상태 판정 대상**: 리프만 판정할지, 중간CA/루트 만료를 별도 상태로 표시할지 `[미결 Q-CHAIN]`
- **서버 요약 상태 집계 규칙**: 서버 단위 상태는 최악(가장 위험한) 인증서 상태로 집계하고, 인증서 단위 목록은 그대로 유지한다. `[제안 — Q-AGG]`

**표시 항목**: 식별 정보, 발급자, 주체, 유효 시작일, 만료일. SAN/CN 추가 표시 여부 `[미결 Q-SAN]`

#### 3.1.5 만료 모니터링

- 만료일과 남은 일수를 계산한다.
- 정상, 만료 임박, 만료, 조회 실패, 인증서 미발견, 확인 필요 상태를 표시한다. *(0.1은 5종이었고 '인증서 미발견'이 누락 — §5 참조)*
- 경고 기준은 설정 가능한 요구사항으로 정의하되 구체적인 기본 일수는 미결로 둔다. `[미결 Q-WARN]`

**만료 판정 규칙** (0.1에서 "검토 과정에서 확정"으로 유보 → 요구사항 수준으로 명시) `[제안 — Q-EXPRULE]`
- 판정 필드: X.509 `notAfter`
- 시각 정규화: 모든 시각을 **UTC로 정규화**하고 ISO 8601(`YYYY-MM-DDTHH:MM:SSZ`)로 표기
- 경계 포함 여부: `now >= notAfter` → 만료(경계 포함), `now >= notAfter − T` → 만료 임박(경계 포함)
- **판정 기준 시각**: 관리 서버(수집) 시각을 기준으로 하고, 대상 서버 시계는 판정에 사용하지 않는다. `[제안 — Q-CLOCKSKEW]`
- **잔여 일수 계산**: `floor((notAfter_UTC − 기준시각_UTC) / 86400)`. 소수 처리·경계값 규칙은 `[미결 Q-DAYCALC]`
- **notBefore가 미래인 인증서**(아직 유효하지 않음)의 상태 `[미결 Q-NOTBEFORE]`

**경고 기준 미설정 시 동작**: `[미결 Q-WARNDEFAULT]`

#### 3.1.6 현황 확인

- 서버별 인증서 상태를 목록으로 확인한다.
- 문제가 있는 서버와 인증서를 구분할 수 있다.
- 마지막 조회 시각과 조회 결과를 표시한다.
- 목록 정렬·필터·강조 표시 등 사용성 기준 `[미결 Q-UX]`
- **'마지막 조회 시각'이 성공 조회만 기록하는지, 실패 조회도 갱신하는지** 명시 필요 `[미결 Q-LASTSEEN]`

### 3.2 후속 기능 (P1)

- 조회 결과 및 실패 이력의 **장기 보관**
- 이메일 등 알림 채널 연동
- 조회 일정 관리(자동 반복 조회)
- 운영 현황 요약 및 보고서
- 이력 기반 KPI 측정
- P1 항목의 실제 구현 순서는 MVP 검증 이후 확정한다. `[미결 Q-P1ORDER]`

> **0.2 변경**: 0.1의 §8 수용 기준 7번('반복 조회 이력 확인 범위')이 본 P1 항목과 충돌했다. 0.2에서는 해당 기준을 **P1로 이관**하고, P0에는 '마지막 조회 시각·결과 표시'(AC-6)만 유지한다. `[제안 — Q-HISTORY]`

### 3.3 MVP 제외

- 인증서 자동 발급 및 갱신
- 인증서 파일의 운영 서버 배포·교체
- 개인키 생성·배포·교체
- Windows, AIX 및 네트워크·보안 장비 연동
- 공인·사설 CA API 통합
- 상용 서비스 수준의 고가용성 및 재해복구 기능
- **CRL/OCSP 등 폐기 상태 확인** (0.1에 명시적 제외 없음 → 추가) `[제안 — Q-REVOCATION]`
- **DER, PKCS#12/JKS, PKCS#11 컨테이너 파싱** (0.1에 없음 → 추가, 단 §3.1.4 형식 결정에 종속)
- **파일시스템 전체 탐색 기반 인증서 발견**
- **다중 조직(테넌트) 분리**
- **단일 인스턴스 운영 가정**: MVP는 고가용성 목표를 두지 않는다. (0.1은 §6에서 '가용성 목표 미결'로 두어 제외 범위와 모순됐다.)

## 4. 사용자 흐름

1. 관리자가 대상 Linux 서버와 인증서 조회 범위를 등록한다.
2. 시스템이 대상 서버의 SSH 연결 가능 여부를 확인한다. (§3.1.1 판정 기준 적용)
3. 연결이 가능하면 지정된 범위에서 인증서 정보를 조회한다.
4. 인증서 유효기간과 잔여 일수를 계산한다. (§3.1.5 판정 규칙 적용)
5. 결과를 상태별로 분류해 현황 목록에 표시한다. (§5 상태 표 적용)
6. 관리자가 **만료 임박 또는 만료 상태**, **조회 실패·인증서 미발견·확인 필요** 항목을 확인하고 후속 조치를 결정한다.
   > 0.1의 '만료 위험' 표현은 §5에 정의된 상태명이 아니므로 삭제했다.

조회 실패는 정상 상태로 간주하지 않는다. 인증서를 찾지 못한 상황만으로 인증서가 없거나 유효하다고 단정하지 않는다.

**오류 처리 정책** (0.1에 부재 → 신설) `[미결 Q-RETRY]`
- 실패 유형별 표시 메시지, 자동 재시도 횟수·간격, 사용자 노출 수준을 정의한다.
- 원격 서버 stderr 원문 노출 여부를 정의한다(민감 정보 노출 위험).

## 5. 상태 분류 요구사항

| 상태 | 상태 코드 `[제안]` | 의미 | 판정 조건 |
|---|---|---|---|
| 정상 | OK | 경고 기준보다 만료일까지 여유가 있음 | 잔여 일수 > T |
| 만료 임박 | WARN | 남은 기간이 경고 기준 이내 | 0 < 잔여 일수 ≤ T |
| 만료 | EXPIRED | 현재 시점에 유효기간이 종료됨 | 잔여 일수 ≤ 0 |
| 조회 실패 | FETCH_FAIL | 연결 또는 정보 조회에 실패함 | §3.1.3의 6종 원인 중 하나 |
| **인증서 미발견** | **NOT_FOUND** | **지정 조회 위치에 대상 인증서가 없음** | **조회는 성공, 대상 0건** |
| 확인 필요 | UNKNOWN | 형식 오류·필수 정보 누락으로 판정 불가 | 파싱 실패 또는 필수 필드 누락 |

**0.2 변경 사항**
- **'인증서 미발견' 상태를 신설**했다. 0.1은 §3.1·§4·§8에서 '인증서 미발견'을 요구하면서 §5 상태 표에 없어 **문서 내 모순**이었다(Product / Certificate Expert / QA / Documentation 4개 역할이 독립적으로 지적).
- **판정 우선순위**를 정의했다: `조회 실패 > 인증서 미발견 > 확인 필요` `[제안 — Q-PRIORITY]`
- 상태 분류 표를 마크다운 표로 변환했다(0.1은 단락 나열로 표에 렌더링되지 않았다).

**아직 확정되지 않은 값**: 경고 기준 T `[미결 Q-WARN]`, 경계 시각 포함/배타 `[제안]`, 시간대 `[제안: UTC]`, 잔여 일수 소수 처리 `[미결 Q-DAYCALC]`, 시계 오차 처리 `[미결 Q-CLOCKSKEW]`

## 6. 비기능 및 보안 요구사항

### 6.1 일반 비기능 요구사항

- 조회 결과와 실패 원인을 운영자가 이해할 수 있어야 한다.
- 조회 실패와 데이터 누락을 정상 상태로 오인하지 않아야 한다.
- 결과에 마지막 조회 시각을 표시해야 한다.
- 인증서 조회 기능은 인증서나 개인키를 변경하지 않아야 한다.
- 민감한 인증정보가 일반 로그나 화면에 불필요하게 노출되지 않아야 한다.
- 향후 대상 서버 및 인증서 수가 증가할 수 있음을 고려해야 한다.
- 구체적인 성능 목표, 지원 서버 수, 동시 조회 수, 보관 기간은 미결 사항이다. `[미결 Q-SCALE]` `[미결 Q-PERF]`

### 6.2 보안 요구사항 (0.1에 부재 → 신설, Security Reviewer 검토)

| # | 요구사항 | 상태 |
|---|---|---|
| S-1 | SSH 자격증명(개인키·패스프레이즈·비밀번호)의 저장·접근 권한·회전 주기·폐기 절차를 정의한다. | `[미결 Q-CRED]` |
| S-2 | 조회용 SSH 계정은 최소 권한(읽기 전용, sudo 금지, 임의 명령 제한)을 가진다. | `[제안 — Q-ACCT]` |
| S-3 | 조회 대상 경로는 화이트리스트로 제한하고, 상위 디렉터리 이탈·인증서 외 파일 접근을 차단한다. | `[제안 — Q-PATH]` |
| S-4 | '인증서·개인키를 변경하지 않음'의 **검증 방법**(비교 대상·시점)을 정의한다. | `[미결 Q-VERIFY]` |
| S-5 | 감사 추적(수행자·시각·대상 서버·계정·결과)의 생성·보호 요구사항을 정의한다. | `[미결 Q-AUDIT]` |
| S-6 | 관리 기능(서버 등록·경로 지정·결과 조회)에 대한 사용자 인증·권한 통제를 정의한다. | `[미결 Q-UI]` |
| S-7 | 수집 정보(서버명·내부 호스트명·발급자 등)의 민감도 분류와 저장·노출·보관·파기 정책을 정의한다. | `[미결 Q-DATA]` |
| S-8 | 실패 원인 메시지에 민감 정보(경로·계정명·키 지문)가 과다 노출되지 않도록 표시 수준을 정의한다. | `[제안 — Q-ERRMSG]` |

> **보안 검토의 독립성 한계**: 본 검토는 동일 모델의 역할 분리 검토이며, **독립된 사람·기관의 보안 감사가 아니다**. §3.1.2·6.2의 항목은 최종 승인 전 실제 독립 검토가 필요하다.

## 7. 전문 역할 협업 계획

승인 후 다음 7개 역할의 **격리된 서브에이전트 검토**를 수행한다.

| §7 역할명 | 책임 범위 | 산출물 |
|---|---|---|
| Commander | 작업 조정·결과 통합·충돌 조정 | 통합 검토 보고서 |
| Product Analyst | 요구사항·수용 기준·범위 | 요구사항 추적표 |
| Linux & SSH | Linux 서버·SSH 조회 요구사항 | 검토 보고서 |
| Certificate Expert | 인증서 정보·상태 판정 | 상태 판정 근거 |
| Security Reviewer | 보안 요구사항·최소 권한 | 보안 검토 보고서 |
| QA & Test | 테스트 시나리오·예외 조건 | 테스트 계획 |
| Documentation & Release | 문서 일관성·릴리스 기준 | 용어집·릴리스 체크리스트 |

이 방식은 **역할별 컨텍스트를 분리한 검토**이며, 그 자체로 독립된 사람 또는 독립 기관의 보안 감사를 의미하지 않는다. 실제 봇 등록이나 프로필 변경은 별도 작업이다.

## 8. MVP 완료 정의 (Definition of Done)

0.1의 '수용 기준' 8개를 **식별자·검증 방법·대응 요구사항**과 함께 재작성했다.

|---|---|---|---|
| AC-1 | 등록한 서버의 식별 정보를 목록에서 확인할 수 있다 | 등록 서버 목록 표시 확인 | §3.1.1 |
| AC-2 | SSH 연결 성공과 실패를 구분하고, 실패 시 원인 유형이 표시된다 | 정상/실패 테스트 서버 각각 조회, 원인 유형 표시 확인 | §3.1.2, §3.1.3 |
| AC-3 | 인증서의 식별 정보·발급자·주체·유효 시작일·만료일이 표시된다 | 표시 값과 원본 인증서 대조 | §3.1.4 |

| AC-6 | 마지막 조회 시각과 결과를 확인할 수 있다 | 목록 화면 표시 확인 | §3.1.6 |
| AC-7 | 조회 기능이 인증서·개인키를 변경하지 않음을 검증할 수 있다 | 조회 전후 파일 해시·메타데이터 비교 | §6.2 S-4 |

**미해결 의존성**: AC-2·AC-4·AC-5는 `[미결 Q-WARN]` `[미결 Q-DAYCALC]` `[미결 Q-EXPRULE]` `[미결 Q-FAILCLASS]` 확정 전에는 **검증 불가**하다.

**테스트 환경 요구사항** (0.1에 부재 → 신설) `[미결 Q-TESTENV]`
- 운영 서버 접속이 금지되므로(§10), 검증은 **테스트 전용 SSH 서버와 테스트용 인증서 세트**에 의존한다.
- 필요한 최소 구성: 정상 1대, 실패 1대, 상태 6종 샘플 인증서 세트.
- 테스트 인증서의 생성·관리 주체를 정의해야 한다.

**MVP 릴리스 게이트** `[제안]`
- §9의 **차단(Blocking) 미결 질문 0건**
- §8 AC-1~AC-7 전 항목 통과
- 7개 역할 검토 완료 + 용어집(부록 A) 동기화
- 보안·아키텍처 항목은 **별도 독립 검토 후** 오너 승인

## 10. 변경 및 승인 경계

현재 단계에서 허용되는 작업은 **PRD 초안 작성과 문서 검토**뿐이다.

사용자 별도 승인 전까지 다음 작업을 수행하지 않는다.

- GitHub 저장소 생성·수정 및 공개범위 변경
- GitHub 웹 UI를 통한 파일 생성·수정·업로드
- 코드 작성·수정·푸시
- 보안·아키텍처 상세 설계
- 운영 서버 접속 및 실제 인증서 변경

> **0.2 정정**: 0.1 §10은 '7개 역할 검토 실행'을 승인 전 금지 작업으로 열거하면서 §7은 "승인 후 7개 역할 검토를 수행한다"고 기술해, 문서가 스스로의 검토를 금지하는 **순환 조항**이었다. 0.2에서는 **문서 검토는 승인 경계의 예외**로 명시한다. 저장소·코드·설계·운영 접속 금지는 그대로 유지한다.

현재 상태: PRD v0.2-draft 작성 완료. 사용자 검토 및 승인 대기.

## 부록 A. 용어 정의

| 용어 | 정의 | 사용 섹션 |
|---|---|---|
| 인증서 미발견 | 지정 조회 위치에 대상 인증서가 존재하지 않음 | §3.1.4, §5, §8 |
| 조회 실패 | SSH 연결 실패 또는 조회 명령 실패로 인증서 정보를 획득하지 못함 | §3.1.3, §5, §8 |
| 데이터 누락 | 조회는 성공했으나 상태 판정에 필요한 필드가 없음 | §5, §6.1 |
| 형식 오류 | PEM/DER 파싱 실패 등 인증서 구조가 유효하지 않음 | §3.1.4, §5 |
| 확인 필요 | 형식 오류 또는 데이터 누락으로 상태 판정이 불가능한 상태값 | §3.1.4, §5 |
| 만료 임박 | 잔여 일수가 경고 기준 T 이내인 상태 | §5 |
| 만료 | 현재 시점에 인증서 유효기간이 종료된 상태 | §5 |
| 판정 기준 시각 | 잔여 일수·상태를 계산하는 기준 시각 (미확정) | §3.1.5, §5 |

0.1에서 '인증서 미발견'·'조회 실패'·'확인 필요'·'데이터 누락'이 서로 다른 뜻으로 혼용되었다. 이후 본문의 모든 상태 표현은 위 표의 용어만 사용한다.
