1. 프로젝트 목적

CertPilot은 서버 및 인프라 환경의 인증서 상태와 만료 위험을 통합적으로 확인하기 위한 인증서 수명주기 관리 솔루션이다.

첫 번째 MVP에서는 Linux 서버를 대상으로 SSH를 통한 인증서 정보 조회와 만료 모니터링에 집중한다. 인증서 발급·갱신·배포 자동화는 후속 단계로 분리한다.

핵심 목표

Linux 서버별 인증서 현황을 조회한다.

인증서 만료일과 잔여 일수를 확인한다.

만료 임박 및 만료 상태를 식별한다.

연결 실패와 조회 실패를 정상 상태와 구분한다.

향후 다른 운영체제, 인증기관(CA), 네트워크 장비로 확장할 수 있는 요구사항 기반을 마련한다.

2. 대상 사용자

Linux 서버 및 서비스 운영 담당자

TLS 인증서 만료를 관리하는 시스템 관리자

여러 서버의 인증서 현황을 확인해야 하는 인프라 운영 조직

초기 MVP는 단일 조직의 운영 환경을 우선 고려한다. 다중 조직 지원 여부는 미결 사항이다.

3. MVP 범위

3.1 필수 기능(P0)

서버 관리

관리 대상 Linux 서버의 식별 정보를 등록·조회한다.

서버별 인증서 조회 대상과 조회 상태를 구분한다.

실제 SSH 연결 가능 여부를 확인한다.

인증서 조회

사전에 지정한 인증서 위치에서 조회 가능한 인증서 정보를 수집한다.

인증서의 식별 정보, 발급자, 주체, 유효 시작일, 만료일을 표시한다.

조회 실패, 인증서 미발견, 형식 오류를 구분한다.

실제 인증서나 개인키를 변경하지 않는 조회 중심 기능으로 제한한다.

만료 모니터링

만료일과 남은 일수를 계산한다.

정상, 만료 임박, 만료, 조회 실패, 확인 필요 상태를 표시한다.

경고 기준은 설정 가능한 요구사항으로 정의하되 구체적인 기본 일수는 미결로 둔다.

현황 확인

서버별 인증서 상태를 목록으로 확인한다.

문제가 있는 서버와 인증서를 구분할 수 있다.

마지막 조회 시각과 조회 결과를 표시한다.

3.2 후속 기능(P1)

조회 결과 및 실패 이력의 장기 보관

이메일 등 알림 채널 연동

조회 일정 관리

운영 현황 요약 및 보고서

P1 항목의 실제 구현 순서는 MVP 검증 이후 확정한다.

3.3 MVP 제외

인증서 자동 발급 및 갱신

인증서 파일의 운영 서버 배포·교체

개인키 생성·배포·교체

Windows, AIX 및 네트워크·보안 장비 연동

공인·사설 CA API 통합

상용 서비스 수준의 고가용성 및 재해복구 기능

4. 사용자 흐름

관리자가 대상 Linux 서버와 인증서 조회 범위를 등록한다.

시스템이 대상 서버의 SSH 연결 가능 여부를 확인한다.

연결이 가능하면 지정된 범위에서 인증서 정보를 조회한다.

인증서 유효기간과 잔여 일수를 계산한다.

결과를 상태별로 분류해 현황 목록에 표시한다.

관리자가 만료 위험 또는 조회 실패 항목을 확인하고 후속 조치를 결정한다.

조회 실패는 정상 상태로 간주하지 않는다. 인증서를 찾지 못한 상황만으로 인증서가 없거나 유효하다고 단정하지 않는다.

5. 상태 분류 요구사항

상태

의미

정상

경고 기준보다 만료일까지 여유가 있음

만료 임박

만료일까지 남은 기간이 경고 기준 이내임

만료

현재 시점에 인증서 유효기간이 종료됨

조회 실패

연결 또는 정보 조회에 실패함

확인 필요

인증서 형식 오류, 필수 정보 누락 등으로 상태 판정이 불가능함

정확한 경계 시각, 시간대, 경고 일수 및 만료 판정 기준은 검토 과정에서 확정한다.

6. 비기능 요구사항

조회 결과와 실패 원인을 운영자가 이해할 수 있어야 한다.

조회 실패와 데이터 누락을 정상 상태로 오인하지 않아야 한다.

결과에 마지막 조회 시각을 표시해야 한다.

인증서 조회 기능은 인증서나 개인키를 변경하지 않아야 한다.

민감한 인증정보가 일반 로그나 화면에 불필요하게 노출되지 않아야 한다.

향후 대상 서버 및 인증서 수가 증가할 수 있음을 고려해야 한다.

구체적인 성능 목표, 지원 서버 수, 동시 조회 수, 보관 기간 및 가용성 목표는 미결 사항이다.

7. 전문 역할 협업 계획

승인 후 다음 7개 역할의 격리된 서브에이전트 검토를 수행한다.

Commander — 작업 조정 및 결과 통합

Product Analyst — 요구사항 및 수용 기준

Linux & SSH — Linux 서버 및 SSH 조회 요구사항

Certificate Expert — 인증서 정보와 상태 판정

Security Reviewer — 보안 요구사항 검토

QA & Test — 테스트 시나리오 및 예외 조건

Documentation & Release — 문서 일관성 및 릴리스 기준

이 방식은 역할별 컨텍스트를 분리한 검토이며, 그 자체로 독립된 사람 또는 독립 기관의 보안 감사를 의미하지 않는다. 실제 봇 등록이나 프로필 변경은 별도 작업이다.

8. MVP 수용 기준

등록한 서버를 식별할 수 있다.

SSH 연결 성공과 실패를 구분할 수 있다.

조회 가능한 인증서의 주요 정보와 만료일을 표시할 수 있다.

잔여 일수를 계산하고 상태를 분류할 수 있다.

조회 실패와 인증서 미발견을 정상 상태와 구분할 수 있다.

마지막 조회 시각과 결과를 확인할 수 있다.

반복 조회 시 결과를 비교하거나 이력을 확인할 수 있는 범위가 정의되어 있다.

조회 기능이 인증서나 개인키를 변경하지 않는다는 조건을 검증할 수 있다.

반복 조회 이력의 구체적인 저장 방식은 설계 단계에서 결정하며, 현재 문서에서는 기술적 구현을 지정하지 않는다.

9. 미결 질문

초기 관리 대상 서버 수는 몇 대인가?

인증서 조회 대상은 HTTPS/TLS 서버 인증서만인가, 디스크에 저장된 인증서 파일도 포함하는가?

기본 만료 경고 기준은 며칠 전으로 할 것인가?

인증서 조회 범위는 서버별로 지정할 것인가, 표준 경로를 우선 적용할 것인가?

SSH 접근에 사용할 인증 방식과 운영상 제약은 무엇인가?

조회 일정과 알림은 MVP 필수인가, 후속 기능인가?

조회 결과와 이력은 얼마 동안 보관해야 하는가?

초기 MVP의 성능 및 대상 규모 목표는 무엇인가?

관리 화면과 사용자 인증은 MVP에 포함되는가?

최초 배포 환경과 운영 방식은 무엇인가?

이 항목들은 승인되지 않은 설계 결정을 방지하기 위해 임의로 확정하지 않는다.
